Compilation latency vs. code quality

Each point is one configuration: a backend plus its options. A point is plotted only if every selected kernel compiled and returned the reference checksum. The line connects the Pareto frontier, the configurations that no other configuration beats on both axes. Click a point to inspect it.

Where compilation time goes

Compile phases of the selected configuration and the frontier configurations, for the selected kernels (mean milliseconds per compilation).

LLVM pass ablation

Each row removes every instance of one pass from the expanded default pipeline and compares the result with the unmodified expanded pipeline. A negative compile change means the pass costs that much compile time. A positive runtime change means the code is that much slower without the pass. Passes in the top-left of the trade-off are cheap to keep and costly to lose.

Greedy pipeline construction

Starting from an empty LLVM pipeline, each step appends the candidate pass with the best runtime gain per millisecond of added compile time (geometric mean over the measured kernels). Every candidate evaluated along the way is in the scatter plot under the llvm-greedy sweep.
