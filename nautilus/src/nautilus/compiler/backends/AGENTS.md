# Backends: notes for agents

A backend implements `CompilationBackend` (`CompilationBackend.hpp`):
`compile(ir, dumpHandler, options, statistics)`, its exception-propagation
mode and the IR optimization level it needs. Built-in backends are registered
in `CompilationBackend.cpp`; plugins call `CompilationBackendRegistry::registerBackend`.

| Backend | Directory | Notes |
|---|---|---|
| `asmjit` | `asmjit/` | `X64LoweringProvider`, `A64LoweringProvider` over AsmJit's `Compiler`; register allocation is AsmJit's (`third_party/asmjit`, Nautilus patches marked `[Nautilus]`); post-RA peepholes. Check generated code with `dump.after_asmjit_assembly` |
| `tbc` | `tbc/` | threaded bytecode with tail-call dispatch; `tbc.mode=jit` uses copy-and-patch stencils (`tbc/jit`, regenerated by the `tbc-regen-stencils` target, Clang ≥ 19) |
| `mlir` | `mlir/` | IR → MLIR → LLVM → ORC JIT; needs the MLIR download (`full` preset) |
| `cpp` | `cpp/` | C++ source compiled by the system compiler into a shared library; slow (~20 ms+), for debugging |

- **Intrinsics:** plugins register native functions in `ir/IntrinsicRegistry`;
  a backend may replace the call with inline code (`asmjit/intrinsics/`,
  `mlir/intrinsics/`). The native function must stay a correct fallback.
- **Exceptions:** backends without unwind tables (`asmjit`, `tbc`) catch
  through capture thunks (`CapturedExceptionTransport`); MLIR code unwinds
  natively.
- **Every backend change** needs `nautilus-execution-tests` on that backend and
  the fuzzer replay; for `asmjit`, also diff the assembly dumps before and
  after (`perf-investigation` skill). Patches to `third_party/asmjit` must keep
  the `[Nautilus]` markers.

## NIR backends (0.4)

- `nir/NirBackend.hpp` is the 0.4 interface (`NirBackend::compile(shared_ptr<const nir::Module>, CompileContext)`) with
  a registry; it lives next to `CompilationBackend` until the cut-over. `tbc/TBCNirLowering.cpp` lowers SSA NIR into the
  same `TBCProgram` as the 0.3 lowering, so dispatch skins, stencils and the executable are shared.
- D10/D11 are lowered in bytecode, not in handlers, so the stencils do not change: a checked `div`/`rem` compares and
  branches to a cold block that calls `nautilus_rt_throw_arith` through its capture thunk, shift amounts are masked,
  `fptosi`/`fptoui` call the saturating helpers of `nir/NirRuntime.cpp`.
- `tools/nir-run` (`nautilus-nir-run`) compiles a `.nir` file and runs its `; run @f(args) = result` directives;
  ctest runs `test/data/nir-run/*.nir` on `tbc` in three modes. Add a file there for every NIR operation a backend
  handles.
- The execution tests also run on the pseudo-backends `nir-tbc` and `nir-tbc-jit`: `tracing.nirChain=true` converts the
  trace to SSA NIR (0.3 tracer -> `toPreSSA` -> conversion) and attaches it to the IR graph, and the `nirtbc` backend
  compiles that NIR with `tbc` on NIR. Both go away at the cut-over.
