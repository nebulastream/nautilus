# Nautilus Runtime Options

Nautilus provides various runtime options to customize the compilation. Options come in two scopes:

- **Engine** – passed when initializing the Nautilus engine (`NautilusEngine(options)`). They configure the
  engine-owned, built-once compiler and therefore apply to every module compiled by that engine. Engine-only options
  cannot be overridden per module.
- **Module** – every option below can be set on the engine to provide an engine-wide default. The options marked
  *Module* in the **Scope** column can additionally be **overridden for an individual compiled module**, either by
  passing a `ModuleOptions` to `engine.createModule(overrides)` or by calling `module.setOption(name, value)` before
  `module.compile()`. A module inherits all engine-wide values and overrides only what it sets.

See [engine.md](engine.md) for how to create modules and override options per module.

| Option                                      | Default | Scope | Type | Code | Description |
|---------------------------------------------|----------|---------|------|------|------------------------------------------------------------------------------------------------------------------------------------------------------|
| engine.compilation=[true,false]             | true     | Engine  | bool | no | Activates the compilation of nautilus functions. If the flag is false, all nautilus functions will be directly invoked, which is handy for debugging. |
| engine.backend=[mlir,cpp,tbc,asmjit]        | -        | Engine  | enum | no | Pins a single compilation backend: the engine compiles single-tier, synchronously, with exactly this backend (no tier-0 compile, no background promotion). When unset, the engine runs the default tiered compilation. |
| engine.tier0.backend / engine.tier1.backend | see desc. | Engine  | string | no | Configures the fast (tier 0) and optimized (tier 1) backends for tiered compilation. Both must be set to override the defaults; ignored when `engine.backend` is set. By default tier 1 is `mlir` and tier 0 is selected by availability in the order `asmjit`, `tbc`, `interpreter`. Tier 0 also accepts the special value `interpreter`: the module runs uncompiled (direct invocation) until the background tier-1 compilation completes. |
| engine.tiered.backgroundPromotion=[true,false] | true  | Engine  | bool | no | **Deprecated alias** of `engine.tiered.promotion` (`false` maps to the internal value `none`, `true` to the default). When true, the engine compiles with the tier-0 backend immediately and promotes to the tier-1 backend in the background. When false, it compiles single-tier with the tier-1 backend (synchronous, no promotion). |
| engine.tiered.promotion=[eager,manual] | eager | Engine | enum | no | When a module is promoted to tier 1: `eager` right after conversion, `manual` only on `CompiledModule::promote()`. The value `none` exists only as the target of the deprecated `engine.tiered.backgroundPromotion=false`. |
| engine.normalizeFunctionNames=[true,false]  | false    | Module  | bool | no | Generates normalized function names (runtimeFunc0, runtimeFunc1, etc.) during tracing instead of using actual function names. Useful for deterministic output and testing. |
| engine.foldStaticConstants=[true,false]     | true     | Module  | bool | yes | Folds, while tracing, operations over values C++ already knows: the byte offset of `ptr + n`, `ptr[n]`, `ptr.get(&S::field)`, `++`/`--` for a raw integer or `static_val` `n` is traced as one constant (`ptr + 0` as a copy), a traced offset into a byte pointer is not multiplied by 1, and a literal in `val OP literal` is traced as a constant of the type the operator converts it to instead of a constant plus a `CAST` (when that conversion is exact for every value of the literal's type). No traced value is consulted, so this is sound in loops and across branches. Set it to `false` to trace these operations unfolded, e.g. to compare traces. See [pointers.md](pointers.md#what-pointer-arithmetic-traces). |
| engine.demangleFunctionNames=[true,false]   | true     | Module  | bool | no | Demangles C++ function names to human-readable format when they are resolved (see `resolveFunctionNames`). When disabled, uses mangled names as-is. Ignored if normalizeFunctionNames is enabled. |
| engine.resolveFunctionNames=[true,false]    | false (true if `debug`/`perf`) | Module  | bool | no | Resolves the symbol names of `invoke()`d native functions and destructors (`dladdr` + demangling, after tracing and cached process-wide) so the IR, dumps and generated code name them. `dladdr` scans the symbol table of the containing object and can cost about 1 ms per callee in large binaries, and names never change the generated code's behaviour -- callees are identified by address -- so by default they are resolved only when the compiled code will be inspected, i.e. when `debug`, `perf` or `perf.sample` is set; otherwise such callees are named `fnN`. Setting this option explicitly overrides that default. `normalizeFunctionNames` does not depend on it. |
| engine.logStatistics=[true,false]           | false    | Module  | bool | no | Logs compilation statistics (timings, entity counts) after compilation.                                                                              |
| dump.all=[true,false]                       | false    | Module  | bool | no | Dumbs intermediate representations all compilation steps.                                                                                             |
| dump.copySites=[true,false]                 | false    | Module  | bool | no | Dumps `copy_sites.txt`: every copy recorded while tracing (an `ASSIGN` to a fresh value, made by a `val` copy constructor), grouped by the C++ call chain that made it, from the copy up to the first frame outside nautilus, and by that frame alone. Use it to find the copies that dominate tracing time and remove them where they are made (`const&` parameters, moves). Frames resolve to `function (file:line)` when the binaries have debug information and `ENABLE_STACKTRACE` is on. Not included in `dump.all`: resolving the stacks is slow. |
| dump.after_tracing=[true,false]             | false    | Module  | bool | no | Dumbs traces directly after trace generation.                                                                                                         |
| dump.after_ir_creation=[true,false]         | false    | Module  | bool | no | Dumbs the nautilus ir after generation.                                                                                                               |
| dump.after_mlir_generation=[true,false]     | false    | Module  | bool | no | Dumbs the generated mlir if the MLIR backend is used. `region()` annotations on the emitted ops come from the IR location map, so they are present only when `debug` or `perf` is also set. |
| dump.after_llvm_generation=[true,false]     | false    | Module  | bool | no | Dumbs the generated llvm if the MLIR backend is used.                                                                                                 |
| dump.after_cpp_generation=[true,false]      | false    | Module  | bool | no | Dumbs the generated cpp code if the CPP backend is used.                                                                                              |
| dump.after_tbc_generation=[true,false]      | false    | Module  | bool | no | Dumps the generated threaded bytecode if the tbc backend is used. |
| dump.after_asmjit_generation=[true,false]   | false    | Module  | bool | no | Dumps the instruction stream the AsmJit backend generated, before assembling. |
| dump.after_asmjit_assembly=[true,false]     | false    | Module  | bool | no | Dumps the machine code the AsmJit backend assembled, as a disassembly. |
| dump.console=[true,false]                   | false    | Module  | bool | no | Enables the dumping of intermediate compilation steps to the console.                                                                                 |
| dump.file=[true,false]                      | true     | Module  | bool | no | Enables the dumping of intermediate compilation steps to a temp folder.                                                                               |
| dump.graph=[true,false]                     | false    | Module  | bool | no | Dumps a graph representation in either (mermaid or graphvit) to a file.                                                                               |
| dump.graph.type=[mermaid,graphviz]          | graphviz | Module  | enum | no | Sets the type of the graph.                                                                                                                           |
| dump.graph.full=[true,false]                | false    | Module  | bool | no | Represents both data and control-flow (full=true) or only the control-flow (full=false).                                                              |
| ir.runPasses=[true,false]                   | true     | Module  | bool | yes | Runs the IR pass pipeline at all. Off, nothing runs on the IR, not even the exception-handling analyses the backends lower landing pads from.        |
| ir.runOptimizationPasses=[true,false]       | see desc. | Module | bool | yes | Pins how much of the IR optimization pipeline runs: `true` every optimization pass (constant folding, algebraic simplification, branch folding, empty-block elimination, block merging, dead-code elimination, block-argument pruning, attribute inference, and the opt-in passes below), `false` none of them. Unset, the backends that compile the graph decide: the interpreters and `asmjit` execute the IR as it is and take every pass; `mlir` gets the same cleanups from LLVM's pipeline and takes only block-argument pruning, which LLVM is measurably slower without. A two-tier compile takes the most any of its tiers asks for, since both compile the same graph. The exception-handling analyses run regardless. |
| ir.disableDeadCodeElimination=[true,false]  | false    | Module  | bool | yes | Disables the pass that removes pure, unused operations (constants, casts, arithmetic) from the IR.                                                    |
| ir.disableAlgebraicSimplification=[true,false] | false | Module  | bool | yes | Disables local algebraic simplifications (identities, bitwise/boolean folds, cast collapsing, constant-to-right canonicalization) in the IR.          |
| ir.disableConstantBranchFolding=[true,false] | false   | Module  | bool | yes | Disables folding `if`s with a compile-time-constant or duplicate-arm condition into unconditional branches and sweeping the resulting unreachable blocks. |
| ir.disableBlockMerging=[true,false]         | false    | Module  | bool | yes | Disables merging blocks that are the sole target of an unconditional branch into their predecessor (collapsing single-predecessor chains).            |
| ir.disableBlockArgumentPruning=[true,false] | false    | Module  | bool | yes | Disables removing block arguments that are unused or receive the identical, dominating value from every predecessor (entry-block arguments are never touched). |
| ir.enableLocalCSE=[true,false]              | false    | Module  | bool | yes | Enables block-local common-subexpression elimination over computed pure operations (opt-in pending a benchmark sweep before it becomes default-on). Loads and constants are never CSE'd. |
| ir.enableLICM=[true,false]                  | false    | Module  | bool | yes | Enables hoisting loop-invariant pure operations into a natural loop's preheader (opt-in; loads and possibly-trapping divisions are never hoisted).    |
| optimizationLevel=[0,1,2,3]                 | 3 (0 if `debug`) | Module | int | yes | Sets the LLVM optimization level for the code-generation if the MLIR backend is used. Overrides the `-O0` clamp `debug` otherwise applies. |
| debug=[true,false]                          | false    | Module  | bool | yes | Top-level gate for DWARF debug-info generation in the MLIR backend, so a debugger can step through and print values in JIT-compiled code. DWARF line-table locations are attached from a Nautilus-IR dump written for this purpose, the LLVM codegen level is clamped (`Less`, and `optimizationLevel` to `0` unless set explicitly) so debug values stay accurate, the MLIR inliner is skipped so frames stay predictable, every `$N` gets a shadow alloca + `dbg.declare`, and the JIT-linked object is registered with the debugger through the GDB JIT interface. A no-op when false. |
| perf=[true,false]                           | false    | Module  | bool | no | Emits perf jitdump records (`JIT_CODE_LOAD` / `JIT_CODE_DEBUG_INFO` / `JIT_CODE_UNWINDING_INFO`) for every JIT-linked object, so `perf record` + `perf inject --jit` can symbolize and attribute samples -- down to `region()` scopes -- inside JIT-compiled code. Linux/ELF only; a no-op with a warning elsewhere. Independent of `debug`: on its own it keeps the requested optimization level and the MLIR inliner running, so the profile reflects *production-optimized* code, the actual point of this option. Setting `debug` and `perf` together still works (`debug`'s `-O0` clamp wins, with a one-time warning that the resulting profile is not representative) -- `optimizationLevel` set explicitly overrides that clamp either way. See `docs/profiling.md` for a full `perf record` / `perf inject` / `perf report` recipe. |
| perf.sample=[true,false]                    | false    | Module  | bool | no | Publishes every compiled code range, with its `region()`-qualified name, into the process-wide `JitSymbolRegistry`, so a sampling profiler running *inside* the process can name JIT frames -- no `perf record`, no `perf inject --jit`, no jitdump file. This is what the `nautilus-profiling` plugin's `profiling::Sampler` resolves against; see `docs/perf.md`. Independent of `perf`: the two write the same names for an in-process and an out-of-process reader respectively, and either, both or neither may be set. Like `perf` it clamps nothing, so the profile reflects production-optimized code. Needs the MLIR backend pinned (`engine.backend=mlir`), since tier-0 backends register nothing. Linux only. |
| mlir.enableMultithreading=[true,false]      | true     | Module  | bool | no | Allows MLIR Backend to use multiple threads.                                                                                                          |
| mlir.enableIntrinsics=[true,false]          | true     | Module  | bool | yes | Registers the MLIR intrinsic plugins for this compilation.                                                                                            |
| mlir.inline_invoke_calls=[true,false]       | false    | Module  | bool | yes | Allow MLIR Backend to inline functions that were tagged with NAUTILUS_INLINE                                                                          |
| mlir.eager_compilation=[true,false]         | false    | Module  | bool | no | Generates machine code during compilation, so the compile statistics include it and the first call does not pay for it. When disabled, LLVM generates it on the first call of a compiled function. |
| tbc.mode=[interp,jit,auto]                  | interp   | Module  | enum | yes | Execution mode of the tbc backend: `interp` runs the dispatch-loop interpreter; `jit` stitches copy-and-patch native code (throws when this build cannot execute it: needs a generated stencil table for the target, a Clang 19+ build, no ASan); `auto` uses the JIT when available and degrades to the interpreter. |
| tbc.dispatch=[auto,tailcall,goto,switch]    | auto     | Module  | enum | no | Interpreter dispatch skin of the tbc backend; `auto` picks the strongest the build supports (tail-call threading on Clang, computed goto on GCC, switch elsewhere). Unavailable requests degrade silently.            |
| tbc.stackSizeKb                             | 1024     | Module  | int | no | Size of the tbc backend's per-thread VM stack in KiB.                                                                                                 |
| tbc.registerAllocator=[true,false]          | true     | Module  | bool | yes | Enables the linear register allocator in the tbc backend's lowering.                                                                                  |
| tbc.coalescing=[true,false]                 | true     | Module  | bool | yes | Emits minimal MOV sequences for block-edge parallel copies in the tbc backend.                                                                        |
| tbc.superinstructions=[true,false]          | true     | Module  | bool | yes | Fuses single-use comparisons into two-word compare-and-branch instructions in the tbc backend.                                                        |
| tbc.immediates=[true,false]                 | true     | Module  | bool | yes | Folds small constant operands into 16-bit immediate fields in the tbc backend.                                                                        |
| asmjit.enableIntrinsics=[true,false]        | true     | Module  | bool | yes | Registers the AsmJit intrinsic plugins for this compilation.                                                                                          |
| asmjit.enablePostRAPeephole=[true,false]    | true     | Module  | bool | yes | Enables post-register-allocation peephole optimizations in the AsmJit backend.                                                                        |
| asmjit.enableBranchFusion=[true,false]      | true     | Module  | bool | yes | Fuses a compare into the conditional branch that is its only consumer in the AsmJit backend (x86-64: cmp+jcc instead of cmp+setcc+movzx+test+jz; ARM64: cmp+b.cond, or cbz/cbnz against zero, instead of cmp+cset+cbz). |
| asmjit.enableConstFolding=[true,false]      | true     | Module  | bool | yes | Defers integer/bool/ptr constants in the AsmJit backend; consumers fold them as immediate operands (add/sub/cmp/shift/imul/and/or/xor; ARM64 adds cmn and logical immediates, and folds block parameters fed one constant on every edge) or rematerialise per use. |
| asmjit.enableSelectCmov=[true,false]        | true     | Module  | bool | yes | Lowers selects branch-free in the AsmJit backend (x86-64: cmov for integers; ARM64: csel/fcsel).                                                      |
| asmjit.enableLazyNarrowing=[true,false]     | true     | Module  | bool | yes | Lets narrow (8/16/32-bit) integer results of add/sub/mul/not/shl/and/or/xor/select and narrow block parameters carry garbage above their width in the AsmJit backend; consumers that read the full register (div/mod, right shifts, casts to float, 64-bit arithmetic, mixed-width compares, calls) re-extend on demand, 32-bit compares use the 32-bit registers (W registers on ARM64). Keeps the re-extension out of loop-carried dependency chains. |
| asmjit.enableAddressFusion=[true,false]     | true     | Module  | bool | yes | Folds pointer/64-bit address adds into the memory operands of the loads and stores that use them in the AsmJit backend. x86-64: `base + index * {1,2,4,8} + disp`, or one `lea` when materialised. ARM64: `[base, #disp]` and `[base, index, lsl #k]` with k the access size's log2, including an i32/ui32 index read through `sxtw`/`uxtw` without its widening cast, or one shifted/extended-register `add` when materialised. |
| asmjit.enableInlining=[true,false]          | true     | Module  | bool | yes | Lowers the body of a small in-module callee (one block of plain value operations, no calls or allocas) in place of the call in the AsmJit backend. |
| asmjit.inliningMaxOperations=[int]          | 24       | Module  | int | yes | Largest callee, in IR operations, that `asmjit.enableInlining` inlines.                                                                              |
| asmjit.enableLoopRotation=[true,false]      | true     | Module  | bool | yes | Repeats a loop header's fused compare at the end of the back edge, jumping straight into the body, instead of jumping back to the header (AsmJit backend; needs `asmjit.enableBranchFusion`). |
| asmjit.enableTailDuplication=[true,false]   | true     | Module  | bool | yes | Lowers a copy of an already emitted small merge block (at most six plain value operations, ending in an unconditional branch) in place of the jump to it, saving a taken branch on that path (AsmJit ARM64 backend). |

## Environment Variables

| Variable                   | Description                                                                                                                                                                                          |
|----------------------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| NAUTILUS_STATISTICS_FILE   | Path of a file that every compilation appends its statistics to, as one JSON object per line (the entries `engine.logStatistics` reports). Measures an application's compilations without changing its options. |
| NAUTILUS_OPTIONS           | Options layered over every engine's own, as `key=value` pairs separated by `;` (e.g. `engine.backend=asmjit;mlir.eager_compilation=true`). `true`/`false` set booleans, numbers set integers or doubles, anything else a string. Reconfigures an application's compilations without changing its code. |
